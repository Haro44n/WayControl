## Implemented

- Renamed project packages, Rust crates, daemon binary, systemd service, Android namespace/application ID and labels to WayControl. Existing `~/.config/hyprcontrol` daemon data is moved to `~/.config/waycontrol` on first startup when the new directory is absent; `HYPRCONTROL_BIND_ADDR` remains a fallback for existing service overrides.
- Added the `waycontrol-compositor` contract with compositor identity, environment detection, and granular workspace/window/monitor/event capabilities. Detection recognizes Hyprland, Sway, Niri, KDE KWin, GNOME, and unknown sessions. CI exercises Sway in a headless compositor, Niri in a nested compositor, and KWin with its virtual compositor; a user's own Sway/Niri/Plasma session remains unvalidated. KWin advertises only workspace list/switch/events. GNOME Wayland uses its optional versioned extension bridge when enabled; GNOME X11 and missing/incompatible bridges expose no compositor capabilities. Unknown sessions also expose no compositor capabilities.
- Added `waycontrol-backend-sway` with bounded Sway IPC framing, workspace/window/output queries, safely quoted workspace commands, container-ID validation, window actions, and event forwarding into the daemon's existing stream. A headless Sway CI test verifies live workspace/window/output queries, workspace event delivery, and all advertised window actions. Sway monitor power and lock screen are explicitly unavailable.
- Added `waycontrol-backend-niri` using Niri's newline-delimited JSON socket protocol. It queries workspaces/windows/outputs, exposes safe ID-based workspace/window actions, and forwards the bounded event stream. Niri fullscreen toggles are not advertised because the documented Window IPC model has no fullscreen state; per-monitor power and lock screen are unavailable. Protocol fixtures and nested live-compositor CI both cover the adapter. Shared `WorkspaceId` supports named IDs while retaining numeric JSON compatibility for existing Hyprland clients; Android sends workspace IDs opaquely.
- Added `waycontrol-backend-kwin` for virtual workspace listing, switching, and workspace-change events through KWin's `org.kde.KWin.VirtualDesktopManager` D-Bus interface. Its capabilities explicitly exclude window and monitor controls. Unit D-Bus mocks and a nested virtual KWin live test cover the adapter; validation in a full Plasma session remains outstanding. Desktop property decoding accepts both signed and unsigned position types observed across KWin builds.
- Added `waycontrol-backend-gnome` plus an optional GNOME Shell extension. It exposes fixed D-Bus v1 methods for workspace/window reads, switching/focus/move/fullscreen/close, and bounded change events. The adapter verifies extension version at daemon startup and advertises capabilities only for GNOME Wayland with a compatible enabled extension. Floating state is represented as nullable across the API; existing adapters keep their true/false values. The Arch package includes extension files without enabling them. GNOME Shell 45–51 are declared in extension metadata; nested GNOME Shell 46 CI passed in runs [43087284157](https://github.com/Haro44n/WayControl/actions/runs/43087284157) and [43093154181](https://github.com/Haro44n/WayControl/actions/runs/43093154181). A physical GNOME session has not been tested.
- Moved the existing Hyprland IPC integration behind the separate `waycontrol-backend-hyprland` crate and `WaylandBackend::Hyprland` adapter. Host system controls and telemetry remain independent of the compositor API. Protocol window IDs are now validated as bounded opaque safe identifiers; the Hyprland adapter retains its stricter hexadecimal address validation.
- Injected compositor and host-system backends separately into the API. Power/audio/media operations remain available independent of compositor capabilities; screen lock is negotiated as a compositor operation and calls Hyprlock only through the Hyprland adapter.
- `desktop.info` now returns detected compositor metadata and negotiated capabilities. Android treats missing capability fields as unavailable, filters workspace/window navigation, conditionally shows individual actions, skips unsupported data/event requests, and keeps Home/System/Settings available.

Settings provides persistent 1/2/5-second telemetry refresh choices for Home/System; other tabs poll five times less often, and refresh work pauses outside the foreground. Window focus/move/floating/fullscreen actions are available; closing a window shows a confirmation dialog.

Missing state is shown as unavailable; the OS name comes from `/etc/os-release` without launching a process.

Audio/media shortcuts appear only when their backend reports availability.
