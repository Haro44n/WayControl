# WayControl progress

**Your desktop. Your control.**

## Release status: PARTIAL — v0.1 acceptance not yet complete

The Rust daemon, authenticated HTTPS API, Android Compose client, workspace/window controls, live Hyprland event stream, core telemetry, and initial monitor/audio/media/power actions are implemented. Builds and host integration checks pass. An Android 36 emulator configured to 1080×2400 at 420 dpi has completed the pinned-TLS pairing flow, encrypted credential restore, live data display, navigation, and server-loss/restart reconnection checks. A physical Poco M5 check remains outstanding.

## Implemented

- Renamed project packages, Rust crates, daemon binary, systemd service, Android namespace/application ID and labels to WayControl. Existing `~/.config/hyprcontrol` daemon data is moved to `~/.config/waycontrol` on first startup when the new directory is absent; `HYPRCONTROL_BIND_ADDR` remains a fallback for existing service overrides.
- Added the `waycontrol-compositor` contract with compositor identity, environment detection, and granular workspace/window/monitor/event capabilities. Detection recognizes Hyprland, Sway, Niri, KDE KWin, GNOME, and unknown sessions. Hyprland has live loopback coverage; Sway and Niri have adapters with protocol-fixture coverage but still need live session validation. KWin advertises workspace list/switch/events, with D-Bus mock coverage but no live Plasma test yet; GNOME and unknown sessions expose no compositor capabilities and receive `unsupported_operation` for compositor requests.
- Added `waycontrol-backend-sway` with bounded Sway IPC framing, workspace/window/output queries, safely quoted workspace commands, container-ID validation, window actions, and event forwarding into the daemon's existing stream. Sway monitor power and lock screen are explicitly unavailable.
- Added `waycontrol-backend-niri` using Niri's newline-delimited JSON socket protocol. It queries workspaces/windows/outputs, exposes safe ID-based workspace/window actions, and forwards the bounded event stream. Niri fullscreen toggles are not advertised because the documented Window IPC model has no fullscreen state; per-monitor power and lock screen are unavailable. Both Sway and Niri adapters have protocol-fixture tests, with live-session tests still outstanding. Shared `WorkspaceId` supports named IDs while retaining numeric JSON compatibility for existing Hyprland clients; Android sends workspace IDs opaquely.
- Added `waycontrol-backend-kwin` for virtual workspace listing, switching, and workspace-change events through KWin's `org.kde.KWin.VirtualDesktopManager` D-Bus interface. Its capabilities explicitly exclude window and monitor controls; the session D-Bus integration still needs live Plasma validation. GNOME remains detected and explicitly unsupported while its remote-control options need further investigation.
- Moved the existing Hyprland IPC integration behind the separate `waycontrol-backend-hyprland` crate and `WaylandBackend::Hyprland` adapter. Host system controls and telemetry remain independent of the compositor API. Protocol window IDs are now validated as bounded opaque safe identifiers; the Hyprland adapter retains its stricter hexadecimal address validation.
- Injected compositor and host-system backends separately into the API. Power/audio/media operations remain available independent of compositor capabilities; screen lock is negotiated as a compositor operation and calls Hyprlock only through the Hyprland adapter.
- `desktop.info` now returns detected compositor metadata and negotiated capabilities. Android treats missing capability fields as unavailable, filters workspace/window navigation, conditionally shows individual actions, skips unsupported data/event requests, and keeps Home/System/Settings available.

- HTTPS daemon with a persistent self-signed certificate; the Android client checks its SHA-256 fingerprint and keeps hostname validation enabled.
- Six-digit pairing codes expire after three minutes. Pair requests expire after five minutes and require explicit interactive approval through the local Linux CLI. Pair attempts are limited.
- Random device credentials are returned only after approval. Linux persists credential hashes with restricted file permissions; Android encrypts the credential with AES-GCM and an Android Keystore key. Local `devices`, `approve`, and `revoke` commands are available.
- Typed API operations require a bearer credential. API bodies are limited to 64 KiB; invalid operations, request IDs, and window addresses are rejected. No remote shell operation exists.
- Android Home, Workspaces, Windows, System Monitor, and Settings screens call the backend. Settings provides persistent 1/2/5-second telemetry refresh choices for Home/System; other tabs poll five times less often, and refresh work pauses outside the foreground. Hyprland workspace/window event subscriptions refresh live state. Event subscriptions and refresh work follow Android lifecycle and reconnect. Window focus/move/floating/fullscreen actions are available; closing a window shows a confirmation dialog.
- Home shows the detected OS name, compositor version when Hyprland provides it, active workspace, focused application, and the measured round-trip time of the authenticated `desktop.info` request. Missing state is shown as unavailable; the OS name comes from `/etc/os-release` without launching a process.
- Home also offers a horizontal quick-switch row built from the backend's current workspace list. It sends the existing typed workspace-switch request, disables the active workspace, and stays read-only when switching is not negotiated.
- Home quick actions provide lock, monitor power, output volume/mute, microphone mute, media play/pause, suspend, reboot, and shutdown. Audio/media shortcuts appear only when their backend reports availability. Actions follow compositor capabilities where relevant; turning a monitor off or invoking power actions requires a native confirmation dialog.
- System Monitor retains up to 60 recent valid aggregate CPU and memory utilization samples and plots each as a line chart. Samples are collected at the configured System refresh interval while the screen is active, the history survives navigation between tabs, disconnects clear it, and missing/out-of-range telemetry is omitted rather than shown as zero. Both charts expose their sample count and latest value through accessibility semantics.
- System actions include lock, suspend, shutdown, reboot, volume adjustment, microphone mute toggle, MPRIS play/pause/next/previous, monitor listing, and per-monitor DPMS. Android discovers media players and displays their playback state, title, artist, and album; transport commands target the selected discovered player. Dangerous power and monitor-off actions require Android confirmation. Server operations are fixed allowlist calls with enum arguments and no shell interpolation.
- Audio and media controls are displayed independently from monitor enumeration; unsupported monitor/lock actions remain gated by negotiated compositor capabilities.
- Added authenticated `audio.info`, bounded `audio.volume.set`, typed `audio.output.select`/`audio.input.select`, and `audio.output_mute` toggle operations backed by `wpctl`. The Android System screen lists current PipeWire sinks/sources, allows choosing a listed device, reads output level/mute and default microphone mute state, provides state-aware output/microphone mute buttons, and renders a 0–100% output slider. Host selection validates the numeric ID against the matching current sink/source list before calling `wpctl set-default`. These host-system operations work with unsupported compositor capabilities too.
- Added authenticated `media.info` and player-targeted MPRIS play/pause, next, and previous operations through fixed `playerctl` arguments. Player IDs are validated, rechecked against the live player list before control, and metadata is bounded and stripped of control characters before returning to Android. Per-player MPRIS control capabilities, current position, and track duration are read with a bounded D-Bus property query. The System screen shows discovered player names, playback status, title, artist, album, and position/duration; it hides commands explicitly unsupported by that player. Legacy global play/pause remains available when player discovery returns no players.
- MPRIS artwork is now exposed through authenticated `media.artwork`. The daemon accepts only local `file:///` artwork paths that resolve inside the user's cache directories, rechecks the current track's opaque artwork ID, rejects files over 512 KiB, and sniffs PNG/JPEG/WebP/GIF signatures. Android requests one current-player cover only while the System screen is open, bounds encoded data and decoded dimensions, and renders it as a small square image.
- Added local automation profiles for Gaming, Development, Away, Eco, and Custom. Profiles persist in Android private preferences and support ordered application launch, workspace switch, volume set, media pause, screen lock, and suspend actions. The editor validates each action, profiles can be enabled or disabled, destructive suspend actions require confirmation, and execution results report ordered steps and stop at the first failure. Application launch is a typed authenticated operation that accepts one validated desktop entry ID and invokes fixed `gtk-launch` arguments; no shell action is exposed.
- Added opt-in-by-bind IPv4 LAN discovery: when HTTPS is bound to a specific RFC1918 or link-local address, the daemon listens on that same address at UDP 8766. It answers only the exact bounded probe from private/link-local clients, rate-limits responses, caps clients and sanitizes the host name; announcements contain only protocol version/name/HTTPS port, never a certificate fingerprint or pairing secret. Android Settings can scan and select a discovered address, but keeps certificate fingerprint entry and Linux approval mandatory. Loopback, wildcard, public, and IPv6 binds do not enable discovery, and firewall configuration is untouched.
- Added `waycontrold pairing-info --qr` to render a terminal QR containing only the private-LAN HTTPS endpoint, current certificate fingerprint, six-digit code, and code expiration. Android Settings scans it with Google Play services Code Scanner, validates HTTPS/private IPv4, certificate fingerprint, code format, and remaining lifetime before filling pairing fields. It does not request camera permission, send a pairing request automatically, or bypass Linux-side approval; manual pairing remains available without Google Play services. QR generation is disabled for loopback, wildcard, public, and IPv6 endpoints.
- Hyprland controls use Lua dispatcher objects on current Hyprland versions and fall back to legacy dispatcher strings when Lua evaluation is unavailable.
- Hyprland window-to-workspace moves now use `follow = false` in the Lua dispatcher and `movetoworkspacesilent` in the legacy fallback, preserving the current workspace. Mock IPC verifies both exact command paths without moving a live window.
- Real aggregate and per-core CPU utilization, optional per-core frequency, and optional per-core temperature from Intel `coretemp` hwmon sensors are exposed, alongside three Linux load averages, RAM/swap, uptime, per-interface IPv4/IPv6 addresses, link state, active default-route status and receive/transmit rates, and NVML GPU utilization, temperature, VRAM, power, optional fan speed, graphics clock and power limit. Missing measurements stay unavailable.
- Added compositor-independent storage telemetry from `/proc/self/mounts` and `statvfs`, with Linux mount escape decoding, pseudo-filesystem filtering, bounded mount enumeration, and total/used/available bytes. Android System Monitor displays mounted storage capacity when available.
- Added a systemd user unit, Arch installation/pairing instructions, Android release build configuration, and a reusable live loopback integration harness at `scripts/test-loopback.py`.
- Updated Rust CI to install `dbus-daemon` and run the workspace suite inside an isolated D-Bus session for KWin adapter tests.
